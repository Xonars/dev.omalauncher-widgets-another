# OMA · обновление

Интерфейс: `../76-oma-update-app.owl`.
`repository.py` читает `/root/dev.omalauncher-another` и сравнивает выбранную
локальную или удалённую ветку с `upstream/main` (SimonSchubert/omalauncher).
`origin/main` — опубликованный форк Xonars/dev.omalauncher-another.

Кнопка обновления получает refs обоих remotes, без checkout, merge, push или
изменения рабочих файлов. Время последнего успешного fetch хранится отдельно
для каждого remote в `~/.cache/oma-updater/repository-sync.json`. При ошибке
сохраняются прежние данные и показывается ошибка. Параллельный fetch защищён flock.
Списки ограничены: 30 коммитов, 60 веток и 60 файлов. Полные diff доступны в терминале.
Счётчики ahead/behind считают коммиты по истории; git cherry отдельно показывает
патчи, не эквивалентные изменениям Симона (без merge-коммитов).

Сборка, резервные копии, подпись и журналы остаются в существующем
`~/.local/share/oma-updater/updater.py`: сборка из origin/main, независимо от
выбранной для просмотра ветки. Старый APK остаётся доступен до успешной новой сборки.
Фоновая операция продолжается после закрытия приложения.

Проверки:

    python -m unittest discover -s oma-update -p 'test_*.py'
    python /root/.local/share/oma-updater/test_updater.py
    owl-check 76-oma-update-app.owl

Главный экран показывает состояние APK и основные действия. Сравнение Git находится
в разделе «Репозиторий», вывод команд — в «Журнале».

Новая сборка состоит из восьми этапов: исходники, резервная копия, подготовка,
создание APK, тесты приложения, тесты OWL, Android Lint, проверка APK.
`build-main.sh` выполняет переданную задачу Gradle; без аргументов собирает APK.
Сборщик записывает названия этапов в `steps`, их длительности в `stage_durations`,
суммы XML-отчётов в `test_results.app` и `test_results.owl` (tests, failures,
errors, skipped, suites). Результаты сбрасываются при новом запуске; при ошибке
тестов XML читается перед остановкой. Следующие этапы при ошибке не запускаются,
предыдущий APK сохраняется. Прогресс означает число завершённых этапов, а не
оценку оставшегося времени. Старые статусы из пяти этапов тоже отображаются.

## Интерфейс

«Главная» ведёт по шагам: проверка GitHub, сборка, установка. Готовый APK и
причина ошибки показаны до подробных этапов. Завершённые этапы и результаты
тестов раскрываются кнопкой; активная сборка всегда показывает ход работы.
«Исходники» позволяет быстро сравнить опубликованный origin/main или локальную
ветку с Симоном. Проверка GitHub получает сведения, без push и merge.
«Журнал» позволяет копировать вывод; очистка требует второго нажатия.

## Передача задачи Codex

В «Журнале» кнопка «Интегрировать upstream» открывает Codex через OWL
`ask(prompt, "codex")`. При ошибке доступна также кнопка «Исправить ошибку».
Задача содержит пути к status.json, build.log и сборочной копии. Агенту поручается
завершить интеграцию/исправление в основном репозитории, коммит и обычный push;
сборка, тесты, lint и установка остаются под управлением пользователя.

После агента «Проверить исправления и собрать» запускает continue_build.py:
проверяет main, отсутствие незавершённых операций Git и несохранённых изменений,
совпадение HEAD с полученным origin/main. Для интеграции дополнительно получает
upstream/main и требует включения его истории. Ошибка проверки не запускает
сборщик. Успех запускает полный новый build с APK, тестами и lint, а не
продолжение старых задач Gradle. Ожидание агента сохраняется между открытиями.
