# Советы

## Очистка и сброс терминала
Чтобы очистить терминал, используйте команду ниже или нажмите Ctrl+L на клавиатуре.

```[clear](/man/clear)```

Если отображение терминала нарушилось, например после случайного вывода двоичного файла через cat или less, восстановите его командой reset.

```[reset](/man/reset)```

## Список последних команд
Команда history показывает историю выполненных команд.

```[history](/man/history)```

Найти команду в истории по запросу:

```[history](/man/history) | [grep](/man/grep) [query]```

Или нажмите Ctrl+R для поиска и выполнения команд из истории.

## Закрытие зависшего окна или приложения
Выполните команду и нажмите на зависшее окно.

```[xkill](/man/xkill)```

Либо найдите идентификатор процесса приложения и завершите его.

```[ps](/man/ps) ax | [grep](/man/grep) firefox```
```[processID] ?? S 0:00.22 firefox```
```[kill](/man/kill) [processID]```

## Автодополнение клавишей Tab
Автодополнение экономит время. Например, чтобы удалить файл с длинным именем, введите первые символы имени и нажмите Tab. Если вариантов несколько, нажмите Tab дважды, чтобы увидеть их список.

## Временные псевдонимы
Экономьте время и создавайте псевдонимы для наиболее часто используемых команд. Псевдонимы похожи на пользовательские ярлыки.

```alias [name]="[command]"```

Пример: Узнайте свой внешний IP.

```alias publicip="[curl](/man/curl) ifconfig.me"```

## Постоянные псевдонимы
Используйте псевдонимы между сеансами или даже дистрибутивами.

Узнайте какая у вас оболочка: 
```[echo](/man/echo) $0```

Bash
```[vim](/man/vim) ~/.bashrc```

ZSH
```[vim](/man/vim) ~/.zshrc```

Fish
```[vim](/man/vim) ~/.config/fish/config.fish```

Найдите место в файле, где вы хотите хранить псевдонимы. Обычно вы найдете их в конце файла.

```alias h="[history](/man/history)"```

## Последовательное выполнение команд
Автоматически выполнять несколько команд подряд. Независимо от того, не выполнена ли одна из команд:

```command1 ; command2 ; command3```

При разделении команд оператором && следующая команда выполняется, только если предыдущая завершилась успешно.

```command1 && command2```

При разделении команд оператором || следующая команда выполняется, только если предыдущая завершилась с ошибкой.

```command1 || command2```

## Синтаксис команды
Чтобы узнать синтаксис команды, лучше всего просмотреть страницу руководства:

```[man](/man/man) [command]```

Если в вашей системе нет man-страницы, что случается редко, вы можете проверить, есть ли у команды справочная страница, самым распространенным способом:

```[command] --help```

TLDR — очень полезный инструмент, который дает общие примеры использования команд.

```[tldr](/man/tldr) [command]```

## Перемещение курсора и редактирование строки

|    |  |
|------------|--------|
| **ctrl + u** | Очистить все перед курсором |
| **ctrl + a** | К началу строки |
| **ctrl + e** | До конца строки |
| **ctrl + f** | Вперед на один символ |
| **ctrl + b** | Назад на один символ |
| **ctrl + w** | Вырезать последнее слово |

## Перенаправление
Вы можете перенаправить стандартный ввод, вывод и ошибку, добавив эти последовательности после команды.

|        |                                                                                                                    |
|--------|--------------------------------------------------------------------------------------------------------------------|
| **>** | отправить вывод в файл (перезаписать и уничтожить все, что уже есть в файле) |
| | `[echo](/man/echo) "Write output to file" > example.txt` |
| **>>** | добавить вывод в файл |
| | `[echo](/man/echo) "Append this to file" >> example.txt` |
| **<** | взять данные из файла |
| | `[cowsay](/man/cowsay) < example.txt` |
| **2>** | отправлять сообщения об ошибках в файл (перезапись). (Это означает, что ошибки могут быть направлены отдельно от обычного вывода.) |
| | `[rm](/man/rm) -vf folder1 file1 > out.txt 2> err.txt` |

## Специальные символы в командах
Специальные символы оболочки интерпретируются оболочкой сразу после подачи команды. Например, если вы наберете ls *.bak, оболочка преобразует *.bak в список всех файлов в текущей папке, имена которых заканчиваются на .bak. Команда ls никогда не видит звездочку. Поэтому, если вы хотите найти файлы, в именах которых действительно есть звездочка, вам нужно экранировать звездочку, чтобы оболочка не смогла ее интерпретировать.

|          |                                                                                                                             |
|----------|----------------------------------------------------------------------------------------------------------------------------------------|
| **\\** | экранирует обратную косую черту и другие специальные символы |
| **\*** | означает что угодно (в том числе ничего) |
|          | `[find](/man/find) ex*.txt` |
| **?** | обозначает любой одиночный символ |
|          | `[find](/man/find) ex?mple.txt` |
| **[]** | содержит шаблоны для сопоставления одного символа |
|          | `[find](/man/find) ex[abc]mple.txt` |
| **()** | запускает содержимое круглых скобок в дочерней оболочке |
|          | `[pwd](/man/pwd) && ([cd](/man/cd) /etc) && [pwd](/man/pwd)` |
| **;** | разделяет команды в одной строке |
|          | `[echo](/man/echo) Hi ; [uname](/man/uname)` |
| **''** | Содержимое одинарных кавычек передается команде без какой-либо интерпретации.                                                |
|          | `[find](/man/find) '(echo abc)'*` |
| **``** | Содержимое обратных кавычек запускается как команда, а ее вывод используется как часть этой команды |
|          | `[echo](/man/echo) \`[uname](/man/uname)\`` |
| **""** | Содержимое кавычек рассматривается как один аргумент; специальные символы внутри кавычек, кроме $ и обратных кавычек, не интерпретируются оболочкой. |
|          | `[cd](/man/cd) "untitled folder"` |
| **\|** | Каналы позволяют отправлять вывод команды другой команде.                                                                    |
|          | `[fortune](/man/fortune) \| [cowsay](/man/cowsay)` |
| **&** | Запустите команду в фоновом режиме.                                                                                                       |
|          | `[cowsay](/man/cowsay) &` |
| **&&** | Выполняйте вторую команду только в том случае, если первая была успешной.                                                                       |
|          | `[ping](/man/ping) localhost -c 1 && [cowsay](/man/cowsay) great` |
| **\|\|** | Выполняйте вторую команду только в том случае, если первая не удалась.                                                                     |
|          | `[ping](/man/ping) "not.reachable" -c 1 \|\| [cowsay](/man/cowsay) sorry` |
| **>>** | Эти символы используются для перенаправления.                                                                                                |
| **!!** | Повторите последнюю команду |
|          | `[sudo](/man/sudo) !!` |
| **!*** | Измените команду, сохраните все аргументы |
|          | `[tail](/man/tail) !*` |
| **^** | Быстрая подмена истории, замена одной строки на другую.                                                                            |
|          | `^png^xcf^` |
| **#** | Превращает строку в комментарий; строка никак не обрабатывается.                                                                   |
|          | `# hint text` |

Не путайте специальные символы оболочки со специальными символами в регулярных выражениях. Регулярные выражения необходимо защищать от оболочки, заключая их в одинарные кавычки.
## Просмотр прав доступа к файлу

```[ls](/man/ls) -l [file]```

| Позиция | Значение |
|----------|---------|
| 1 | Тип файла: «-» для обычного файла, «d» для каталога, «l» для символической ссылки. |
| 2-4 | Разрешения владельца (rwx) |
| 5-7 | Разрешения группы (rwx) |
| 8-10 | Другие разрешения (rwx) |

Пример: `-rwxr--r--` означает, что у владельца есть разрешения на чтение, запись и выполнение, но у группы и других есть только права на чтение.

## Изменить права доступа к файлу

```[chmod](/man/chmod) [modification] [file]```

Пример. Предоставьте группе доступ на чтение и запись к файлу test.txt.

```[chmod](/man/chmod) g+rw test.txt```

Группы разрешений:

|       |  |
|-------|---------|
| **u** | Владелец |
| **g** | Группа |
| **o** | Другое |

Типы разрешений:

|       |  |
|-------|---------|
| **r** | Чтение |
| **w** | Запись |
| **x** | Выполнение |

Операторы для команды модификации: **+** (плюс) и **-** (минус).

## Числовая запись прав доступа
Пример: разрешить владельцу чтение и запись, группе — чтение, остальным — запретить доступ.

```[chmod](/man/chmod) 640 test.txt```

Первое число представляет разрешения **владельца**, второе — разрешения **группы**, а последнее — разрешения для всех остальных пользователей. Каждая цифра — сумма значений разрешений **rwx**: чтение — 4, запись — 2, выполнение — 1.

| Разрешение | Значение |
|------------|--------|
| r | 4 |
| w | 2 |
| x | 1 |

## Запуск команд в фоновом режиме
Если команда выполняется долго, вы можете приостановить ее с помощью **Ctrl+Z**, а затем возобновить в фоновом режиме.

```[bg](/man/bg)```

Чтобы вернуть фоновое задание на передний план:

```[fg](/man/fg)```

Чтобы просмотреть все фоновые задания в текущем сеансе:

```[jobs](/man/jobs)```

Если вы хотите, чтобы команда продолжала работать даже после выхода из системы, используйте nohup.

```[nohup](/man/nohup) [command] &```

Для длительных задач или управления несколькими сеансами терминала используйте tmux. Он позволяет отключать и повторно подключать сеансы, поэтому ваша работа сохраняется при отключении.

```[tmux](/man/tmux) new -s mysession```

Отключитесь от сеанса с **Ctrl+B**, затем **D**. Подключитесь позже с помощью:

```[tmux](/man/tmux) attach -t mysession```

## Планирование задач с помощью cron
Отредактируйте crontab вашего пользователя, чтобы запланировать повторяющиеся задачи.

```[crontab](/man/crontab) -e```

Каждая строка в crontab имеет формат из пяти полей:

| Поле | Значение |
|-------|-------|
| минута | 0–59 |
| Час | 0–23 |
| День месяца | 1 - 31 |
| Месяц | 1–12 |
| День недели | 0–7 (0 и 7 — воскресенье) |

Пример: запускайте сценарий резервного копирования каждый день в 2 часа ночи.

```0 2 * * * /home/user/backup.sh```
